PART 1

Let users edit their own profile

PATCH/users/me

A signed-in user can change their first name, last name and phone number. They can't change their email or role here. The path is /me instead of /{user_id} because the token already tells us who is asking. Nobody can edit somebody else's profile.

aInput schema: UserProfileUpdate

Every field has default=None, like the fixed VehicleUpdate. That's what makes a field optional. The user sends only what they want to change.

schemas/users.py · bottom of file
class UserProfileUpdate(BaseModel):
    first_name: Optional[str] = Field(default=None, min_length=2, max_length=100)
    last_name: Optional[str] = Field(default=None, min_length=2, max_length=100)
    phone_number: Optional[str] = Field(default=None, max_length=15)

bLogic: update_me

Phone numbers are unique in the database. If the user picks a number someone else already has, saving would crash with a 500. So we check first and send a clear 400. The User.id != current_user.id part lets a user send their own number again.

controllers/users.py · top of file: add UserProfileUpdate to this import
from schemas.users import UserCreate, UserLogin, UserProfileUpdate
controllers/users.py · bottom of file
async def update_me(db: AsyncSession, current_user: User, user_input: UserProfileUpdate):
    # only the fields the user actually sent (skip missing ones and nulls)
    update_data = user_input.model_dump(exclude_unset=True, exclude_none=True)

    # phone numbers are unique, so check nobody else has the new one
    if "phone_number" in update_data:
        existing_phone_number = await db.execute(
            select(User).where(
                User.phone_number == update_data["phone_number"],
                User.id != current_user.id
            )
        )

        if existing_phone_number.scalar_one_or_none() is not None:
            raise HTTPException(
                status_code=400,
                detail="A user with this phonenumber already exists"
            )

    for key, value in update_data.items():
        setattr(current_user, key, value)

    await db.flush()
    await db.refresh(current_user)

    return {"success": True, "message": "profile updated successfully", "data": current_user}
Why no db.add()?

get_current_user loaded this user with the same database session the route uses, because FastAPI gives one request one get_db. The session is already tracking the user, so changing the attributes is enough. get_db commits when the request finishes.

Order matters

Keep every /me route above @router.get("/{user_id}"). FastAPI checks routes from top to bottom. If /{user_id} comes first, it tries to read "me" as a UUID and returns 422.

PART 2 · THE BIG ONE

UserOut: never send the password hash

POST/users/register GET/users/ GET/users/me PATCH/users/me GET/users/{user_id}

Every user endpoint returns the User object from the database, and FastAPI sends every column it has. That includes password. Here is GET /users/me right now:

Why a hash is still a secret

A bcrypt hash can't be turned back into the password, but it can be guessed against. Someone with the hash can try millions of common passwords on their own computer, and our server never knows. And GET /users/ doesn't need a login, so right now anyone can download every user's hash with one request.

The rule

The database model is not the response. You decide what leaves the server.

The User model describes what we store. A response schema describes what we send. They are different things and get different classes. Write an output schema for every model you return.

aWrite the output schemas

UserOut lists the fields a client is allowed to see, and password isn't one of them. Our responses are wrapped in success, message and data, so we also describe the wrapper: one with a single user and one with a list.

from_attributes=True lets Pydantic read from a database object (user.first_name), not only from a dict (user["first_name"]).

schemas/users.py · top of file: replace the imports
from typing import Optional
from uuid import UUID
from datetime import datetime
from pydantic import BaseModel, EmailStr, Field, ConfigDict
schemas/users.py · bottom of file
class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: UUID
    first_name: str
    last_name: str
    email: str
    phone_number: Optional[str] = None
    role: str
    created_at: datetime


class UserResponse(BaseModel):
    success: bool
    message: str
    data: UserOut


class UserListResponse(BaseModel):
    success: bool
    message: str
    data: list[UserOut]

bPut the schemas on the routes with response_model

So far every route had response_model=None, which means "send whatever I return". With a response model, FastAPI checks the return value against the schema and drops every field the schema doesn't list. The controller still returns the full User, but the password never leaves the route.

PART 3

The 4 steps for building any endpoint

Last week we talked about the order we build in. You just followed it for PATCH /users/me. Here it is written down, so every new endpoint follows the same steps:

Schemas → Logic → Route → Test. If a test fails, the status code tells you which step to go back to.

Play a trip for PATCH /users/me:
1

Schemas

schemas/<thing>.py
  • In: what does the client send? Which fields are required and which are optional? What are the limits (length, type)?
  • Out: what do we send back? Which fields must never leave the server?

Done when you have an input class (if the request has a body) and an output class.

2

Logic

controllers/<thing>.py
  • Write the steps in plain words first: find it → check it → change it → save → return.
  • Each check gets its own error: not there → 404, not yours → 403, bad or duplicate data → 400.

Done when the function returns {"success", "message", "data"}.

3

Route

routes/<thing>.py
  • Method + path: GET reads, POST creates, PATCH changes part of something.
  • Does it need a login? Add Depends(get_current_user).
  • Set response_model. Put fixed paths like /me above /{id}.

Done when the endpoint shows up in Swagger.

4

Test

http://127.0.0.1:8000/docs
  • Test the success case first, then every error you wrote in step 2.
  • Read the whole response body. Is anything there that shouldn't be?
  • If something fails, use the table below to find which step to go back to.

Done when every case gives the status you planned.

?When a test fails, which step do I go back to?

You getIt usually meansGo back to

schemas/users.py
from typing import Optional
from uuid import UUID
from datetime import datetime
from pydantic import BaseModel, EmailStr, Field, ConfigDict


class UserCreate(BaseModel):
    first_name: str = Field(..., min_length=2, max_length=100)
    last_name: str = Field(..., min_length=2, max_length=100)
    email: EmailStr = Field(...)
    phone_number: Optional[str] = Field(default=None, max_length=15)
    role: Optional[str] = Field(default="user")
    password: str = Field(..., min_length=6, max_length=100)


class UserLogin(BaseModel):
    email: str = Field(...)
    password: str = Field(..., min_length=6, max_length=100)

class UserProfileUpdate(BaseModel):
    first_name: Optional[str] = Field(default=None, min_length=2, max_length=100)
    last_name: Optional[str] = Field(default=None, min_length=2, max_length=100)
    phone_number: Optional[str] = Field(default=None, max_length=15)


class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: UUID
    first_name: str
    last_name: str
    email: str
    phone_number: Optional[str] = None
    role: str
    created_at: datetime


class UserResponse(BaseModel):
    success: bool
    message: str
    data: UserOut


class UserListResponse(BaseModel):
    success: bool
    message: str
    data: list[UserOut]

controllers/users.py

controllers/users.py
from sqlalchemy.ext.asyncio import AsyncSession
from schemas.users import UserCreate, UserLogin, UserProfileUpdate
from sqlalchemy import select
from models import User
from fastapi import HTTPException
from utils.security import hash_password, verify_password
from uuid import UUID
from utils.security import create_access_token


async def create_user(db: AsyncSession, user_input: UserCreate):
    # check if email exists
    existing_email = await db.execute(
        select(User).where(User.email == user_input.email)
    )

    if existing_email.scalar_one_or_none() is not None:
        raise HTTPException(
            status_code=400,
            detail="A user with this email already exists"
        )

    # check if phone_number exists if provided
    if user_input.phone_number:
        existing_phone_number = await db.execute(
            select(User).where(User.phone_number == user_input.phone_number)
        )

        if existing_phone_number.scalar_one_or_none() is not None:
            raise HTTPException(
                status_code=400,
                detail= "A user with this phonenumber already exists"
            )

    new_user = User(
        first_name=user_input.first_name,
        last_name=user_input.last_name,
        email=user_input.email,
        phone_number=user_input.phone_number,
        password=hash_password(user_input.password),
        role="user"
    )


    db.add(new_user)
    await db.flush()
    await db.refresh(new_user)

    return {"success": True, "message": "Account successfully created", "data": new_user}


async def login_user(db: AsyncSession, user_input: UserLogin):
    # Check if email exists
    result = await db.execute(
        select(User).where(User.email == user_input.email)
    )

    user = result.scalar_one_or_none()

    if user is None:
        raise HTTPException(
            status_code=403,
            detail="This account does not exist. Please register"
        )

    
    if not verify_password(user_input.password, user.password):
        raise HTTPException(
            status_code=403,
            detail="Incorrect password"
        )

    access_token = create_access_token(
        data={"user_id": str(user.id),"email": user.email,"role": user.role}
    )

    return {
        "success": True, 
        "message": "logged in successfully",
        "data": {
            "access_token": access_token,
            "token_type": "bearer"
        }
        }



async def get_all_users(db: AsyncSession):

    result = await db.execute(
        select(User)
    )

    users = result.scalars().all()

    return {"success": True, "message": "users retrieved successfully", "data": users}

async def get_user_by_id(db: AsyncSession, user_id: UUID):

    result = await db.execute(
        select(User).where(User.id ==user_id)
    )

    user = result.scalar_one_or_none()

    if user is None:
        raise HTTPException(
            status_code=404,
            detail= "User not found"
        )

    return {"success": True, "message": "user retrieved successfully", "data": user}

async def get_me(current_user:User):
    return {"success": True, "message": "user retrieved successfully", "data": current_user}
