PART 1

Change the Ride model

Look at the Offer a ride screen: the driver picks a car, types where from and where to, the day and time, how many seats and the fare per seat. Compare that with models/ride.py:

  • Seats are missing. A Corolla has 4 passenger seats, but the driver might only offer 3. We need seats_offered.
  • distance_km is required, but no driver will type the distance into a form. We make it optional (nullable=True). Later the app could work it out from a map.

bRecreate the rides table

Our app creates tables with Base.metadata.create_all when it starts. That function only creates tables that don't exist yet. It never changes a table that is already there. So the new column won't appear by itself, and inserting a ride would fail because the database doesn't know seats_offered.

The rides table is empty (we never had a way to add rides), so the simple fix is to drop it and let the app create it again. Make this file in the project root, run it once, then delete it:

drop_rides_table.py · new file, project root
# Run this ONCE, then delete the file.
# create_all() only creates tables that are missing. It never changes a table
# that already exists. The rides table is empty, so we drop it and the app
# creates it again, with the new columns, the next time it starts.
import asyncio
from sqlalchemy import text
from db import engine


async def main():
    async with engine.begin() as conn:
        await conn.execute(text("DROP TABLE IF EXISTS rides"))
    await engine.dispose()
    print("rides table dropped. Start the app to create it again.")

asyncio.run(main())
Terminal
python drop_rides_table.py
Only because it's empty

Dropping a table deletes every row in it. We can do it here because rides has no rows. Never do this to users or vehicles. When a table has real data, we change it with a migration instead (a tool called Alembic, already in requirements.txt). That's a lesson of its own.

PART 2 · SCHEMAS

RideCreate: what a driver sends

POST/rides/

The driver does not send driver_id or status. The token tells us who the driver is, and every new ride starts as "scheduled". If we let the client send those, anyone could offer a ride in someone else's name.

schemas/rides.py · new file
from pydantic import AwareDatetime, BaseModel, Field
from uuid import UUID


class RideCreate(BaseModel):
    vehicle_id: UUID
    origin: str = Field(..., min_length=2, max_length=255)
    destination: str = Field(..., min_length=2, max_length=255)
    # AwareDatetime means the time must say its timezone, e.g. 2026-11-20T07:30:00+01:00
    departure_time: AwareDatetime
    seats_offered: int = Field(..., ge=1)
    fare: float = Field(..., gt=0)
FieldRuleWhy
vehicle_idUUIDPydantic rejects anything that isn't a valid id with 422, before our code runs
departure_timeAwareDatetimeThe time must include its timezone, like +01:00 for Lagos. Without it, 07:30 could mean 07:30 in London or in Lagos.
seats_offeredge=1"greater than or equal to 1": you can't offer 0 seats
faregt=0"greater than 0": a ride can't be free or negative
Reading a time with a timezone

2026-11-20T07:30:00+01:00 means 7:30 on 20 November, one hour ahead of UTC. That's Lagos time. The database stores it in UTC, so the response will show 06:30:00+00:00. Same moment, written differently. The frontend turns it back into 7:30 AM.

PART 3 · LOGIC

Offer, search and get one ride

POST/rides/ GET/rides/ GET/rides/{ride_id}

All of this goes in one new file, controllers/rides.py. We'll write it in four pieces.

aImports, Lagos time, and format_ride

A passenger looking at a ride wants to see the driver's name and the car, not just driver_id and vehicle_id. So every ride we send back includes a small driver and vehicle inside it.

Why build a dict by hand instead of returning the User object? Because the User object has the password hash, email and phone number in it. A passenger should see the driver's name and nothing else. format_ride picks exactly what leaves the server.

controllers/rides.py · new file, start here
from datetime import date, datetime, time, timedelta, timezone
from uuid import UUID

from fastapi import HTTPException
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from models import Ride, User, Vehicle
from schemas.rides import RideCreate

# Lagos is UTC+1 all year (no daylight saving)
LAGOS = timezone(timedelta(hours=1))


def format_ride(ride: Ride, driver: User, vehicle: Vehicle):
    # Build the ride by hand so we only send what passengers may see:
    # no password, no email, no phone, no plate number.
    return {
        "id": ride.id,
        "origin": ride.origin,
        "destination": ride.destination,
        "departure_time": ride.departure_time,
        "arrival_time": ride.arrival_time,
        "fare": ride.fare,
        "status": ride.status,
        "seats_offered": ride.seats_offered,
        "seats_left": ride.seats_offered,  # no bookings yet, so every seat is free
        "driver": {
            "id": driver.id,
            "first_name": driver.first_name,
            "last_name": driver.last_name,
        },
        "vehicle": {
            "make": vehicle.make,
            "model": vehicle.model,
            "colour": vehicle.colour,
            "capacity": vehicle.capacity,
        },
    }
seats_left for now

There are no bookings yet, so every offered seat is still free and seats_left equals seats_offered. In part 2 (bookings) we'll subtract the seats people have booked. The frontend already reads seats_left, so it won't need to change.

bcreate_ride: four checks, then save

Plain words first: find the car → is it yours? → enough seats? → in the future? → save → return. Each check has its own status code, the same way update_vehicle does it.

CheckStatusdetail
No vehicle with that id404Vehicle not found
The vehicle belongs to someone else403You can only offer rides in your own vehicle
More seats than the car has400You can't offer more seats than your vehicle has
The time has already passed400Departure time must be in the future
controllers/rides.py · under format_ride
async def create_ride(db: AsyncSession, user_input: RideCreate, current_user: User):
    # 1. the vehicle must exist
    result = await db.execute(
        select(Vehicle).where(Vehicle.id == user_input.vehicle_id)
    )
    vehicle = result.scalar_one_or_none()

    if vehicle is None:
        raise HTTPException(
            status_code=404,
            detail="Vehicle not found"
        )

    # 2. ...and belong to the person offering the ride
    if vehicle.owner_id != current_user.id:
        raise HTTPException(
            status_code=403,
            detail="You can only offer rides in your own vehicle"
        )

    # 3. you can't offer more seats than the car has
    if user_input.seats_offered > vehicle.capacity:
        raise HTTPException(
            status_code=400,
            detail="You can't offer more seats than your vehicle has"
        )

    # 4. the ride must be in the future
    if user_input.departure_time <= datetime.now(timezone.utc):
        raise HTTPException(
            status_code=400,
            detail="Departure time must be in the future"
        )

    new_ride = Ride(
        driver_id = current_user.id,
        vehicle_id = vehicle.id,
        origin = user_input.origin.strip(),
        destination = user_input.destination.strip(),
        departure_time = user_input.departure_time,
        seats_offered = user_input.seats_offered,
        fare = user_input.fare,
        status = "scheduled",
    )

    db.add(new_ride)
    await db.flush()
    await db.refresh(new_ride)

    return {"success": True, "message": "ride created successfully", "data": format_ride(new_ride, current_user, vehicle)}
Why the frontend cares about the exact detail text

The frontend matches these messages to show the error under the right field. "You can't offer more seats..." shows under Seats to offer; "Departure time must be in the future" shows under Leaving at. Copy them exactly.

csearch_rides: a join, a filter, a day

This is the new idea today. A ride row only has driver_id and vehicle_id. To show names we need the matching user and vehicle rows too. A join asks the database for all three at once, matched up by those ids:

.join(User, Ride.driver_id == User.id) and .join(Vehicle, Ride.vehicle_id == Vehicle.id) give one row per ride: (ride, driver, vehicle). Then format_ride keeps the green bits and drops the crossed-out ones.

Then we narrow it down. Each filter is only added if the passenger sent it:

  • ilike(f"%{origin}%"): contains, ignoring capitals. Searching ikeja finds Ikeja City Mall and Ikeja, Allen Avenue.
  • A day in Lagos: every ride from 00:00 that day up to 00:00 the next day, both in Lagos time. We don't compare dates in UTC, because a ride at 00:30 in Lagos is still the day before in UTC.
  • We always hide rides that already left or aren't scheduled, and sort the earliest first.
controllers/rides.py · under create_ride
async def search_rides(db: AsyncSession, origin: str | None, destination: str | None, day: date | None):
    # Ride + its driver + its vehicle, in one query
    query = (
        select(Ride, User, Vehicle)
        .join(User, Ride.driver_id == User.id)
        .join(Vehicle, Ride.vehicle_id == Vehicle.id)
        .where(Ride.status == "scheduled")
        .where(Ride.departure_time > datetime.now(timezone.utc))
    )

    # ilike = LIKE that ignores capital letters; % means "anything",
    # so "ikeja" finds "Ikeja City Mall"
    if origin:
        query = query.where(Ride.origin.ilike(f"%{origin.strip()}%"))

    if destination:
        query = query.where(Ride.destination.ilike(f"%{destination.strip()}%"))

    # a whole day in Lagos time: from 00:00 up to (not including) 00:00 the next day
    if day:
        start = datetime.combine(day, time.min, tzinfo=LAGOS)
        end = start + timedelta(days=1)
        query = query.where(Ride.departure_time >= start, Ride.departure_time < end)

    query = query.order_by(Ride.departure_time)

    result = await db.execute(query)
    rides = [format_ride(ride, driver, vehicle) for ride, driver, vehicle in result.all()]

    return {"success": True, "message": "rides retrieved successfully", "data": rides}

dget_ride_by_id

The same join, for one ride. one_or_none() gives back the (ride, driver, vehicle) row, or None → 404.

controllers/rides.py · bottom of file
async def get_ride_by_id(db: AsyncSession, ride_id: UUID):
    result = await db.execute(
        select(Ride, User, Vehicle)
        .join(User, Ride.driver_id == User.id)
        .join(Vehicle, Ride.vehicle_id == Vehicle.id)
        .where(Ride.id == ride_id)
    )
    row = result.one_or_none()

    if row is None:
        raise HTTPException(
            status_code=404,
            detail="Ride not found"
        )

    ride, driver, vehicle = row
    return {"success": True, "message": "ride retrieved successfully", "data": format_ride(ride, driver, vehicle)}
PART 4 · ROUTES

Connect them to paths

Only offering a ride needs a login. Searching and viewing a ride are open, like a bus timetable. The search filters are query parameters: function arguments that aren't in the path and aren't a schema, so FastAPI reads them from ?origin=...&day=... in the URL. = None makes each one optional.

routes/rides.py · new file
from datetime import date
from uuid import UUID

from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession

from controllers.rides import create_ride, get_ride_by_id, search_rides
from db import get_db
from models import User
from schemas.rides import RideCreate
from utils.security import get_current_user

router = APIRouter(prefix="/rides")


@router.post("/", response_model=None)
async def offer_ride(user_input: RideCreate, db: AsyncSession = Depends(get_db), current_user: User = Depends(get_current_user)):
    return await create_ride(db, user_input, current_user)


@router.get("/", response_model=None)
async def search(
    origin: str | None = None,
    destination: str | None = None,
    day: date | None = None,
    db: AsyncSession = Depends(get_db),
):
    return await search_rides(db, origin, destination, day)


@router.get("/{ride_id}", response_model=None)
async def get(ride_id: UUID, db: AsyncSession = Depends(get_db)):
    return await get_ride_by_id(db, ride_id)

Keep the trailing slash

The paths are /rides/ with a slash, like /vehicles/. Calling /rides without it makes FastAPI answer with a redirect, and browsers drop the Authorization header on that redirect.

from routes.users import router as user_router
from routes.vehicles import router as vehicles_router
from routes.rides import router as rides_router
from contextlib import asynccontextmanager
from db import engine
from models import Base



@asynccontextmanager
async def lifespan(app: FastAPI):
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    yield
    # Perform any cleanup tasks here

app = FastAPI(
    title="Carona API", 
    version= "0.1.0",
    description="API for Carona carpooling service",
    summary="This API allows users to create and manage carpooling rides, view available rides, and join existing rides.",
    lifespan=lifespan
)

# Browsers block a page from calling an API on another address (origin) unless
# the API says that address is allowed. The allowed frontends come from .env,
# comma-separated, e.g. CORS_ORIGINS=http://localhost:5173,https://carona.example
load_dotenv()
CORS_ORIGINS = [o.strip() for o in os.getenv("CORS_ORIGINS", "").split(",") if o.strip()]

app.add_middleware(
    CORSMiddleware,
    allow_origins=CORS_ORIGINS,
    allow_methods=["*"],
    allow_headers=["*"],  # the frontend sends Content-Type and Authorization
)

app.include_router(user_router)
app.include_router(vehicles_router)
app.include_router(rides_router)


@app.get("/health")
async def health():
    return {"status": "ok"}
